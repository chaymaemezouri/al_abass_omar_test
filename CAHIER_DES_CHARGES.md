# Cahier des charges - Plateforme electorale interactive 2026

## 1. Presentation du projet

Le projet consiste a concevoir et deployer une plateforme electorale moderne, institutionnelle et responsive pour presenter le candidat **AL ABASS Omar**, son programme politique 2026 et un assistant IA officiel capable de repondre aux citoyens en francais, arabe et darija.

La plateforme doit valoriser le candidat, rendre le programme plus accessible, faciliter la consultation des engagements et offrir un canal d'echange intelligent, fiable et rassurant avec les electeurs.

## 2. Contexte

Dans le cadre des elections legislatives 2026, la communication politique doit etre claire, credible et adaptee aux usages numeriques actuels. Les citoyens consultent principalement les contenus depuis mobile, attendent des reponses rapides et souhaitent comprendre les propositions concretes sans devoir lire l'integralite d'un document PDF.

La plateforme doit donc combiner :

- une presentation institutionnelle du candidat ;
- une lecture simplifiee du programme ;
- un assistant IA encadre par une base validee, disponible en francais, arabe et darija ;
- une experience mobile fluide ;
- une identite visuelle premium, sobre et rassurante.

## 3. Objectifs du projet

### Objectif principal

Creer une plateforme politique digitale capable de presenter clairement le programme electoral 2026 et de permettre aux citoyens d'interagir avec un assistant IA officiel.

### Objectifs secondaires

- Renforcer l'image professionnelle du candidat.
- Rendre les engagements politiques faciles a comprendre.
- Mettre en avant les priorites du programme par themes.
- Offrir une experience bilingue francais/arabe avec prise en charge de la darija dans le chatbot.
- Optimiser l'interface pour smartphone, tablette et desktop.
- Permettre le telechargement du programme PDF officiel.
- Garantir que les reponses de l'assistant restent basees uniquement sur le programme valide.

## 4. Public cible

La plateforme s'adresse principalement a :

- citoyens de la circonscription cible ;
- electeurs souhaitant comprendre les engagements du candidat ;
- jeunes utilisateurs habitués aux interfaces mobiles ;
- journalistes, observateurs et acteurs politiques ;
- equipe de campagne souhaitant partager un support officiel et coherent.

## 5. Perimetre fonctionnel

### 5.1 Page d'accueil

La page d'accueil doit presenter immediatement :

- le nom du candidat ;
- la circonscription ;
- le message politique principal ;
- l'image officielle du candidat ;
- les axes majeurs du programme ;
- les boutons d'action principaux ;
- un acces visible a l'assistant IA.

La premiere section doit etre claire, premium, institutionnelle et adaptee aux ecrans mobiles.

### 5.2 Navigation

Le menu doit permettre d'acceder rapidement aux sections principales :

- Accueil ;
- Programme ;
- Engagements ;
- Assistant IA ;
- Changement de langue.

Sur mobile, la navigation doit rester compacte, lisible et sans chevauchement.

### 5.3 Section Programme

La section programme doit presenter les grands axes de maniere interactive :

- production de richesse ;
- besoins essentiels des citoyens ;
- identite, souverainete et unite nationale.

Chaque axe doit contenir :

- un titre ;
- un resume ;
- des sous-themes ;
- des objectifs associes ;
- un acces rapide au chatbot pour demander une precision.

### 5.4 Section Engagements

La plateforme doit afficher les engagements sous forme de cartes modernes.

Chaque engagement doit comporter :

- numero d'objectif ;
- titre ;
- constat ;
- proposition ;
- beneficiaires ;
- indicateur ou echeance ;
- source du programme.

Les cartes doivent etre lisibles sur mobile, avec un espacement reduit mais confortable.

### 5.5 Section Assistant IA

L'assistant IA doit permettre aux citoyens de poser des questions sur le programme.

Fonctionnalites attendues :

- disponibilite en francais, arabe et darija ;
- detection de la langue de la question lorsque cela est possible ;
- reponses en darija lorsque l utilisateur pose sa question en darija arabe ou arabizi ;
- option vocale pour dicter une question ;
- option de lecture audio des reponses lorsque le navigateur le permet ;
- ouverture depuis un bouton flottant ;
- ouverture depuis les boutons de la page d'accueil ;
- interface plein ecran ;
- interface multilingue francais/arabe et comprehension de la darija ;
- suggestions de questions ;
- themes rapides cliquables ;
- affichage des sources ;
- lecture vocale des reponses ;
- saisie vocale si le navigateur le permet ;
- message clair lorsque l'information n'existe pas dans la base validee.

L'assistant ne doit pas repondre a des questions hors programme ou inventer des informations non validees.

### 5.6 Module questions-reponses video

La plateforme doit integrer une section dediee aux questions citoyennes avec des reponses video du candidat.

Objectif du module :

- humaniser la communication politique ;
- permettre aux citoyens de voir et entendre directement le candidat ;
- completer les reponses de l'assistant IA par des explications video ;
- organiser les reponses autour des themes majeurs du programme.

Contenu attendu :

- environ 30 videos courtes du candidat ;
- une question claire associee a chaque video ;
- classement par theme : emploi, sante, education, eau, PME, famille, justice, identite, jeunesse, territoire ;
- miniatures video professionnelles ;
- duree affichee ;
- bouton lecture ;
- possibilite de filtrer par theme ;
- affichage responsive mobile ;
- lien entre certaines reponses du chatbot et les videos correspondantes.

Chaque video doit respecter une coherence editoriale : message court, langage accessible, reponse concrete, posture institutionnelle et ton rassurant.

### 5.7 Telechargement PDF

La plateforme doit proposer le telechargement du programme PDF officiel.

Le bouton doit etre visible, accessible et fonctionner sur desktop comme sur mobile.

### 5.8 Version arabe

La plateforme doit proposer une version arabe complete.

Les elements suivants doivent etre traduits :

- navigation ;
- titres ;
- descriptions ;
- boutons ;
- engagements ;
- axes du programme ;
- interface du chatbot ;
- messages d'aide ;
- sources ;
- suggestions.

Le sens d'affichage doit passer en RTL lorsque la langue arabe est active.

## 6. Exigences graphiques

### 6.1 Identite visuelle

L'identite doit rester coherente avec une communication politique institutionnelle :

- bleu marine profond ;
- blanc ;
- rouge pour les actions principales ;
- touches dorees discretes ;
- typographie lisible et moderne ;
- iconographie sobre.

### 6.2 Style general

Le rendu doit etre :

- professionnel ;
- moderne ;
- rassurant ;
- credible ;
- clair ;
- non surcharge.

Les grandes cartes opaques inutiles doivent etre evitees. Les animations doivent rester sobres et logiques.

### 6.3 Animations

Animations recommandees :

- apparition douce des sections au scroll ;
- leger mouvement sur les cartes au hover ;
- progression animee sur les barres d'indicateurs ;
- chargement anime dans le chatbot ;
- micro-interactions sur les boutons.

Les animations ne doivent jamais nuire a la lisibilite ou a la performance mobile.

## 7. Exigences responsive

La plateforme doit etre optimisee pour :

- mobile : 360 px a 480 px ;
- tablette : 768 px a 1024 px ;
- desktop : 1280 px et plus.

Sur mobile :

- aucun debordement horizontal ;
- boutons pleine largeur si necessaire ;
- titres redimensionnes ;
- images conservees sans deformation ;
- cartes empilees verticalement ;
- chatbot utilisable en plein ecran ;
- bouton flottant non coupe ;
- sections plus compactes.

## 8. Exigences techniques

### 8.1 Stack technique

La plateforme est basee sur une architecture web moderne orientee performance, maintenabilite et experience utilisateur.

Technologies principales :

- React pour la construction de l'interface utilisateur ;
- TypeScript pour securiser le code et reduire les erreurs ;
- TanStack Start pour la structure applicative, le routage et le rendu moderne ;
- Vite pour le developpement rapide et le build de production ;
- Tailwind CSS pour un systeme de design responsive et coherent ;
- Lucide React pour une iconographie moderne, legere et uniforme ;
- API serveur pour connecter l'assistant IA a la base de connaissance validee ;
- Git et GitHub pour le versioning, le suivi des modifications et la livraison du code.

Fonctionnalites techniques prevues :

- gestion bilingue francais/arabe avec support RTL ;
- structure de donnees bilingues pour les contenus du programme ;
- composant chatbot reutilisable ;
- systeme de suggestions de questions ;
- gestion des sources affichees dans les reponses ;
- support micro via l'API SpeechRecognition lorsque disponible ;
- lecture vocale via SpeechSynthesis lorsque disponible ;
- interface responsive adaptee aux smartphones ;
- integration d'assets : images PNG, logo, PDF officiel et futures videos ;
- build de production verifiable avant mise en ligne.

### 8.2 Architecture technique cible

L architecture doit rester claire et evolutive :

- dossier `assets` pour les images, logos, PDF et ressources media ;
- dossier `components` pour les composants reutilisables, notamment le chatbot ;
- dossier `data` pour les contenus structures du programme ;
- dossier `lib` pour les helpers, traductions et utilitaires ;
- dossier `routes` pour les pages et endpoints serveur ;
- endpoint serveur dedie au chatbot afin de ne pas exposer la logique sensible cote navigateur.

Pour le futur module video, il est recommande de prevoir une structure de donnees dediee comprenant :

- identifiant de la video ;
- question affichee ;
- theme ;
- langue ;
- duree ;
- miniature ;
- fichier ou lien video ;
- resume court ;
- relation eventuelle avec un engagement du programme.

### 8.3 Qualite du code

Le code doit respecter :

- composants reutilisables ;
- donnees structurees ;
- separation entre contenu, interface et logique ;
- compatibilite TypeScript ;
- formatage Prettier ;
- absence d'erreurs de build.

### 8.4 Performance

La plateforme doit viser :

- chargement rapide ;
- images optimisees ;
- CSS limite au necessaire ;
- experience fluide sur smartphone ;
- absence de blocage lors de l'ouverture du chatbot.

## 9. Assistant IA - Regles de fonctionnement

L'assistant IA doit respecter les regles suivantes :

- repondre uniquement a partir du programme officiel ;
- citer ou indiquer la source de la reponse ;
- refuser poliment les questions hors programme ;
- ne pas inventer de chiffres, promesses ou positions ;
- adapter la langue de reponse a la langue de la question ;
- accepter la darija en alphabet arabe ou en arabizi ;
- permettre la dictee vocale des questions lorsque le navigateur le supporte ;
- permettre l ecoute audio des reponses lorsque le navigateur le supporte ;
- proposer des questions proches si l'information demandee n'existe pas.

## 10. Accessibilite

La plateforme doit respecter les bonnes pratiques suivantes :

- contrastes suffisants ;
- textes lisibles ;
- boutons accessibles au clavier ;
- labels ARIA sur les actions importantes ;
- focus visible ;
- textes alternatifs sur les images utiles ;
- contenu utilisable sans souris.

## 11. Securite et fiabilite

La plateforme doit :

- proteger la logique du chatbot cote serveur ;
- eviter l'exposition d'informations sensibles ;
- ne pas enregistrer inutilement les donnees personnelles ;
- encadrer strictement le prompt systeme de l'assistant ;
- garantir que les contenus publics sont valides par l'equipe de campagne.

## 12. Livrables attendus

Les livrables du projet sont :

- code source complet ;
- assets visuels integres ;
- programme PDF disponible au telechargement ;
- interface responsive ;
- version francaise ;
- version arabe RTL ;
- chatbot fonctionnel en francais, arabe et darija ;
- option vocale pour poser une question et ecouter certaines reponses ;
- module questions-reponses video avec environ 30 videos du candidat ;
- repository GitHub a jour ;
- build de production valide.

## 13. Criteres d'acceptation

Le projet sera considere comme valide si :

- la page d'accueil s'affiche correctement sur desktop et mobile ;
- la version arabe traduit les nouvelles sections ;
- le chatbot s'ouvre depuis les boutons prevus ;
- l assistant comprend les questions en francais, arabe et darija ;
- les options vocales fonctionnent sur les navigateurs compatibles ;
- la section video permet de consulter les reponses du candidat par theme ;
- les questions rapides fonctionnent ;
- le PDF se telecharge ;
- aucun texte ne chevauche une image ou un bouton ;
- aucun debordement horizontal n'apparait sur mobile ;
- le build de production passe sans erreur ;
- les changements sont pushes vers GitHub.

Des ameliorations futures peuvent etre ajoutees :

- formulaire de contact citoyen ;
- carte interactive de la circonscription ;
- export PDF des engagements ;

- integration analytics respectueuse de la vie privee.

### Priorites du planning

- La version mobile doit etre controlee a chaque etape, pas seulement a la fin.
- Les contenus politiques doivent etre valides avant integration finale.
- Les videos doivent etre livrees avec noms clairs, miniatures et classement par theme.
- L'assistant IA doit etre teste avec des questions en francais, arabe, darija et arabizi.
- Le build de production doit etre valide avant chaque push important.

## 16. Conclusion

Cette plateforme doit devenir un support officiel, clair et interactif pour expliquer le programme electoral 2026 de **AL ABASS Omar**. L'objectif n'est pas seulement de presenter des informations, mais de creer une experience de confiance, capable d'aider chaque citoyen a comprendre les engagements du candidat et a poser ses questions simplement.
